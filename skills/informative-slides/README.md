# informative-slides

발표자 없이 읽어도 이해되는 슬라이드를 한국어·영어 전환이 되는 단일 HTML 파일로 만드는 에이전트 스킬이다.
장마다 머리표, 대상이 드러나는 명사구 제목, 메시지 한 문장, 근거(구조도, 확대 상세도, 표, 라벨 불릿), 출처를
이 순서로 둔다.

## 이 스킬이 막는 문제

| 문제 | 규칙 |
|---|---|
| 정의 없는 용어·약어 | 쓰는 장마다 쉬운 이름과 함께 쓴다 (`느린 1% 요청의 응답 시간 (p99)`) |
| 대상이 없는 제목 | 제목은 대상·측면·범위를 갖춘 명사구, 지표에는 무엇의 지표인지 붙인다 |
| 원자료 기호·지시어 | `B안`, `③`, `해당` 대신 내용으로 부르고 기호는 괄호에 둔다 (`이벤트 기록 테이블 경유 발행(B안)`) |
| 맥락 없는 수치 | 단위, 비교 기준, 조건, 출처를 함께 적는다 |
| 과밀·장식 | 짧은 구로 쓰되 대상과 이름은 남긴다. 흰 배경, 장식 없음, 색은 뜻이 있을 때만(new·crit·연결 색) |
| 장 안의 읽는 순서 부재 | 머리표 → 명사구 제목 → 메시지 한 문장 → 근거 → 출처. 순서가 있는 설명은 단계로 하나씩 보인다 |

덱 구성은 표지 → 결론 요약(리캡: 문제·한 일·근거) → 본문 → 결정 요청이다. 구조와 처리 순서는 논문 그림
수준 구조도로 그리고, 한 부분을 설명할 때는 확대 상세도와 전체 구조 속 위치를 함께 보인다. 처리 순서를
따라가는 구조도와 근거를 하나씩 더하는 불릿은 단계로 나눠 `→`를 누를 때마다 하나씩 보이고, PDF에서는
단계마다 한 쪽이 된다. 모든 글자는 한국어와 영어로 쓰고 `L` 키로 전환한다. 화면 비율은 덱의
`<html data-ratio="16:9">`에서 정한다. 슬라이드 규칙은
[drive-project-forward](https://github.com/JuwonHwang/drive-project-forward)의 `slides/RULES.md`를 기반으로 한다.

## 구성

```
informative-slides/
├── SKILL.md                # 에이전트가 따르는 절차와 규칙
├── assets/template.html    # 슬라이드 골격: 구조도·확대도, 단계, 한영 전환, 화면 비율, 인쇄, 넘침 확인
└── scripts/check_deck.py   # 제목·메시지·분량·출처·약어·기호·한영·넘침 검사
```

## 설치

저장소 루트의 [README](../../README.md)대로 Claude Code 플러그인으로 설치한다.

```
/plugin marketplace add JuwonHwang/informative-slides
/plugin install informative-slides@informative-slides
```

"슬라이드 만들어", "발표 자료 만들어" 같은 요청에서 `informative-slides:informative-slides`가 불린다.

**다른 코딩 에이전트 (Codex, Cursor, Gemini CLI 등)**: 저장소를 받아 두고 요청에 다음 문장을 붙인다. 또는 이 문장을
`AGENTS.md`에 넣는다.

```
슬라이드를 만들 때는 skills/informative-slides/SKILL.md를 먼저 읽고 그 절차를 따른다.
```

## 요청 형식

```
[주제]에 대한 [N]장 슬라이드를 [대상]용으로 만든다.
목적: [정보 공유 / 결정 요청]
핵심 메시지: [한 문장]
다룰 내용:
1. [항목 1]
2. [항목 2]
3. [항목 3]
자료: [파일 경로, 문서, 데이터]
```

예시:

```
사내 문의 자동 분류 시범 운영 결과를 운영팀 리더용 7장 슬라이드로 만든다.
목적: 전면 도입 결정 요청
핵심 메시지: 첫 응답 시간이 절반으로 줄었고, 세 가지를 준비하면 전면 도입할 수 있다.
다룰 내용: 효과 수치, 오분류 원인, 도입 전 준비 사항
자료: reports/pilot-2026q3.md
```

자료에 없는 수치는 지어내지 않고 `[확인 필요: ...]`로 남긴다. 결과를 전달할 때 채울 항목 목록을
함께 알린다.

## 결과물 사용

- 브라우저로 연다. `→`·`Space`는 다음 단계나 다음 장, `←`는 이전, `L`은 한국어/영어 전환이다.
- 검수와 PDF: 함께 배포하는 `slide-review` 스킬이 검수 화면을 연다. 덱이 화면 안에 들어가고, 요소를 클릭해
  의견을 단다. 의견은 덱 옆 `<덱 이름>-feedback.md`에 자동 저장된다. 같은 화면에서 비율과 크기를 바꿔 보고,
  `HTML 저장`과 `PDF 저장`(글꼴 포함, 단계마다 한 쪽)을 한다.
- 브라우저 인쇄(`Cmd/Ctrl+P`)도 장·단계마다 한 쪽으로 나오지만, Safari는 쪽 크기 지정을 무시해 장이 잘린다.

## 검사

```bash
python3 skills/informative-slides/scripts/check_deck.py slides/deck.html
```

제목 목록을 순서대로 출력하고 다음을 보고한다. ERROR가 있으면 종료 코드 1을 반환한다.

- 모호한 제목(`개요`, `결과`, `Overview` 등), 문장 제목(`-다`로 끝남): ERROR
- 메시지(`.lead`)가 없거나 둘 이상: ERROR
- 한국어·영어 짝 불일치, 정의되지 않은 구조도: ERROR
- 화면 넘침(Chrome, Chromium, Edge가 설치된 경우, 두 언어 모두, 마지막 단계 기준): ERROR
- 제목 폭 초과(한글 1, 그 밖의 글자 0.55로 세어 본문 장 40, 표지 26): WARN
- 메시지가 두 문장 이상이거나 두 줄 초과: WARN
- 분량 초과(본문 60어절, 요약 장 50어절), 요약 줄 길이 초과(한글 30자): WARN
- 출처 없는 수치: WARN
- 쉬운 이름 없이 쓴 약어·지표 기호·모델 이름(장마다 확인): WARN
- 내용 이름 없이 쓴 원자료 기호(`B안`, `시나리오 C`), 장 밖을 가리키는 지시어(`해당`, `위의`, `전자`): WARN
- 표지·요약·마무리 누락, 요약의 리캡 누락, `<html data-ratio>` 누락: WARN
