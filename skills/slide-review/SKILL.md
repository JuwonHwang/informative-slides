# 슬라이드 검수

사람이 덱을 보면서 고칠 곳을 가리키고, 에이전트가 그 지점을 정확히 찾아 고치게 한다. 대화로 받은 피드백은 어느 장의 어느 요소인지 불분명하고, 같은 피드백을 두 번 전달하게 만든다. 이 스킬은 의견을 요소 단위로 기록해 그 문제를 없앤다.

## 원칙

1. **의견마다 대상 요소를 기록한다.** 의견마다 장 번호, 요소 종류, 요소 문구 일부, 장 기준 CSS 경로가 붙는다. 에이전트는 이 정보로 요소를 찾는다.
2. **의견은 입력하는 즉시 저장한다.** 검수 화면은 입력할 때마다 서버에 의견을 보낸다. 버튼을 누르지 않고 다른 장으로 넘어가도 의견이 남는다.
3. **의견을 보내는 시점과 검수를 끝내는 시점은 사용자가 정한다.** 사용자는 `피드백 보내기`로 검수를 이어 가면서 지금까지의 의견을 보내고, `검수 완료`로 남은 의견을 보낸 뒤 검수를 끝낸다. 에이전트는 둘 중 하나의 신호가 올 때까지 기다리고, 그 전에 의견을 읽어 작업을 시작하지 않는다.
4. **검수 서버는 쓰는 동안에만 떠 있다.** 검수 화면이 한 번도 연결되지 않은 상태가 60분, 연결된 화면의 신호가 끊긴 상태가 30분, 또는 클릭·키 입력·의견 입력이 없는 상태가 60분 이어지면 서버가 스스로 종료한다. 브라우저는 뒤쪽 탭의 타이머를 늦추거나 멈추므로, 열려 있는 탭도 몇 분 동안 신호를 보내지 않을 수 있다. 서버가 종료되면 검수 화면 위에 빨간 안내가 뜬다. `검수 완료`를 받으면 의견을 더 받지 않고 HTML·PDF 저장만 처리하다가, 검수 화면이 닫히고 1분 또는 조작 없이 10분이 지나면 종료한다. 다음 검수는 `review.py open`이 다시 띄운다.

## 검수 화면

`assets/review.html`이 화면이고 `scripts/review_server.py`가 덱과 화면을 제공하고 의견을 저장한다.

| 자리 | 기능 |
|---|---|
| 상단 막대 | 덱 이름, `◀ ▶` 장 이동과 장 바로가기(`4 / 9 · 제목` 목록에서 고르면 그 장으로 간다), `요소 선택` 켜기·끄기, `비율`, `표시`, `PDF 가로`, 저장 상태, `HTML 저장`, `PDF 저장`, `피드백 보내기`, `검수 완료` |
| 왼쪽 | 덱(덱의 비율 또는 고른 비율). 요소에 마우스를 올리면 점선 테두리, 클릭하면 선택된다. 같은 요소를 다시 클릭하면 상위 블록으로 넓어진다. 의견을 단 요소에 번호 핀이 붙는다 |
| 오른쪽 | 현재 장 제목, 선택한 요소의 의견 입력, 이 장의 의견 목록(누르면 요소 강조와 수정), 장 전체 의견, 의견이 있는 장 번호 |

- `요소 선택`이 켜져 있으면 클릭으로 장이 넘어가지 않는다. 장 이동은 버튼이나 `←`/`→`이다.
- `검수 완료`를 누르면 의견을 보낸 뒤 `HTML 저장`, `PDF 저장`, PDF 설정(`비율`, `PDF 가로`)을 뺀 모든 조작이 막히고 "검수를 마쳤다" 안내가 남는다. 저장은 탭을 닫기 전까지 쓸 수 있다. 탭은 사용자가 닫는다.
- `비율`(덱 설정, 16:9, 16:10, 4:3, 3:2, 1:1, 21:9), `표시`(맞춤, 50~150%, 100%는 PDF 쪽 실제 크기), `PDF 가로`(16, 13.33, 11.69, 20인치, 직접 입력)는 검수 화면과 PDF에만 적용한다. 덱 HTML 파일은 바꾸지 않는다. 덱 설정 비율은 덱의 `<html data-ratio>`이고, 없으면 16:9이다.
- `HTML 저장`과 `PDF 저장`은 Chrome·Edge에서 브라우저 저장 창으로 위치와 파일 이름을 묻는다. Safari·Firefox에는 이 창이 없어 브라우저의 다운로드 설정을 따른다.
- PDF는 서버가 Chrome·Chromium·Edge(Playwright가 설치한 Chromium 포함)로 렌더링한다. 지금 보는 언어, 고른 비율과 가로 길이로 장마다 한 쪽을 만든다. 덱에 단계(`data-step`, `data-steps`)가 있으면 단계마다 별개의 쪽이 된다. Chrome은 쪽 크기를 반올림하므로 서버가 쪽 크기를 정확한 값으로 고친다. 서버 컴퓨터에 이 브라우저가 없으면(예: ssh로 연결한 원격 서버) `PDF 저장`은 사용자 브라우저의 인쇄 창을 연다. 인쇄에도 단계별 쪽, 글꼴, 비율·가로 길이가 적용되지만 쪽 크기 보정은 없고, Safari는 쪽 크기 지정을 무시해 장이 잘린다. Firefox와 Chrome에서 대상을 "PDF로 저장"으로 고른다.
- 글꼴: 서버는 덱을 보여 줄 때와 PDF를 만들 때 이 스킬에 들어 있는 Pretendard(`assets/fonts/`, 굵기 400·500·600·700·800)를 덱에 넣는다. 그래서 검수 화면과 PDF가 같은 글꼴이고, 만드는 컴퓨터에 Pretendard가 없어도 PDF에 Pretendard가 들어간다. 덱 파일은 바꾸지 않는다. 덱이 `font-family`에서 Pretendard를 쓰지 않으면 덱이 지정한 글꼴을 쓴다.
- 인쇄 보정: 서버는 덱을 보여 줄 때 인쇄용 CSS 한 줄(`.slide{container-type:normal}`)을 넣는다. 장에 `container-type:size`가 있으면 Firefox가 인쇄할 때 SVG 구조도의 글자를 그리지 않기 때문이다. 이 보정은 이전 템플릿으로 만든 덱에도 적용된다.
- 덱의 장은 `<section class="slide">`이고, 없으면 `<section>`이다. 장 이동은 덱이 받는 `←`/`→` 키를 검수 화면이 대신 보낸다. 이 두 조건을 갖춘 덱이면 어느 도구로 만들었든 검수할 수 있다.

## 절차

1. **로컬 포트에 검수 화면을 띄운다.** 이 스킬을 쓰면 항상 이 명령으로 연다.

   ```bash
   python3 <스킬 폴더>/scripts/review.py open <덱.html>
   ```

   검수 서버가 이미 떠 있고 그 루트 폴더 안에 덱이 있으면 그 서버를 다시 쓴다. 없으면 빈 로컬 포트(8765부터, `127.0.0.1`에만 연결)에 서버를 백그라운드로 띄운다. 루트 폴더는 덱이 들어 있는 git 저장소의 최상위 폴더이고, git 저장소가 아니면 덱 폴더이다. 검수 화면이 이미 열려 있으면 새 탭을 열지 않고 그 화면이 2초 안에 이 덱의 새 회차로 내용을 바꾼다. 열린 화면은 화면이 실제로 보낸 신호로만 판단하고, 6초 안에 화면이 새 회차로 바뀌었다는 신호가 오지 않으면 브라우저 탭을 새로 연다. 새 탭을 열었으면 그 탭이 이 회차로 첫 신호를 보낼 때까지 15초 기다린다. 출력 JSON의 `connected`는 화면이 실제로 신호를 보냈을 때만 `true`이고, `shown_in`은 `existing review tab`, `new browser tab`, `not confirmed` 중 하나이다. 서버 정보(PID, 포트, 루트)는 `~/.config/informative-slides/review-server.json`에 기록한다.

2. **사용자에게 알린다.** 확인한 것만 알린다. `connected`가 `true`이면 검수 화면을 띄웠다고 쓰고, 무엇을 보면 되는지와 요소를 클릭해 의견을 달고 `검수 완료`를 누르면 된다는 것을 짧게 쓴다. `false`이면 화면이 열린 것을 확인하지 못했다고 쓰고 출력의 `url`을 주어 사용자가 직접 열게 한다. 알리기 전에 `review.py status`의 `running`이 `true`인지도 확인한다.

3. **신호를 기다린다.** 사용자가 `피드백 보내기`를 누르면 덱 옆에 `<덱 이름>-feedback.sent`가, `검수 완료`를 누르면 `<덱 이름>-feedback.done`이 생긴다. 둘 중 하나가 생길 때까지 기다린다.

   ```bash
   until [ -f <덱 이름>-feedback.sent ] || [ -f <open이 출력한 done 경로> ]; do sleep 2; done
   ```

   신호 파일에는 보낸 의견 파일의 경로가 한 줄로 들어 있다. 보낸 의견은 `<덱 이름>-feedback-history/<시각>.md`, `.json`으로 옮겨져 있고, 검수 화면의 의견 목록은 비워진다.

4. **의견을 읽는다.** 신호 파일이 가리키는 `.md`가 사람이 읽는 형태이고, 같은 이름의 `.json`이 같은 내용의 구조 데이터이다. 읽은 뒤 `.sent` 신호 파일은 지운다.

   ```markdown
   ## 5. 위키 검색 답변 정답률 61% → 74%
   - 슬라이드 전체: 내용이 문장으로 길어 와닿지 않는다
   - 1. 제목 "위키 검색 답변 정답률 61% → 74%" (`header:nth-child(1) > h2:nth-child(2)`): 대상이 보이지 않는다
   ```

   CSS 경로는 장(`section`) 기준이다. `section.querySelector(':scope > ' + 경로)`로 요소를 찾는다.

5. **반영한다.**
   - 덱만 고치는 요청이면 의견마다 해당 요소를 고친다.
   - 덱을 만든 스킬을 고치는 중이면, 의견을 덱 하나의 수정으로 끝내지 않는다. 의견이 가리키는 원칙을 찾아 스킬 문서의 해당 원칙을 다시 쓴다. 문장을 덧붙이지 않는다.
   - 지금까지 받은 의견을 누적 목록으로 남기고, 새 덱을 사람에게 보이기 전에 목록 전체와 대조한다. 이전 의견이 다시 어긋나면 고친 뒤에 보인다.
   - 반영한 뒤에는 덱을 만든 스킬의 확인 절차를 다시 실행한다. `informative-slides`로 만든 덱이면 `check_deck.py`를 다시 돌리고 고친 장을 두 언어로 캡처한다. 글자를 고치면 구조도의 상자와 화살표가 깨질 수 있다. 검사가 오류 없이 끝난 뒤에 다시 연다.

6. **이어 가거나 다시 연다.**
   - `피드백 보내기`였으면 검수 화면은 열려 있다. 덱 파일을 고쳐 저장하면 화면이 보던 장에서 덱을 다시 불러온다. 사용자에게 반영했다고 알리고 3단계로 돌아간다.
   - `검수 완료`였으면 서버는 의견을 더 받지 않는다. 다음 회차는 `review.py open`으로 연다. 탭이 열려 있으면 같은 탭이 새 회차로 바뀌고 서버가 의견을 다시 받는다. 탭이 닫혀 서버가 종료되었으면 새로 띄운다. `open`은 지난 회차의 신호 파일을 정리하고 빈 의견 목록으로 시작한다. 이전 회차 의견은 기록 폴더에서 읽는다.

## 파일

| 파일 | 내용 |
|---|---|
| `scripts/review.py` | 검수 화면 열기(`open`), 서버 내리기(`stop`), 상태(`status`). 빈 로컬 포트를 찾아 서버를 띄우고 다시 쓴다. 열린 검수 탭이 있으면 그 탭의 내용을 바꾼다 |
| `scripts/review_server.py` | 루트 폴더 정적 제공, `/__review/<덱>`에 검수 화면, `POST /__feedback`으로 의견 저장, `/__render/<덱>`에 글꼴을 넣은 덱, `/__pdf/<덱>?lang=&ratio=&w=`으로 PDF 생성 |
| `assets/review.html` | 검수 화면 |
| `assets/fonts/` | Pretendard 정적 글꼴 5개와 라이선스(SIL Open Font License 1.1) |
| `<덱>-feedback.md` | 의견, 사람이 읽는 형태 |
| `<덱>-feedback.json` | 의견, 구조 데이터. 검수 화면을 다시 열면 이 파일에서 의견을 불러온다 |
| `<덱>-feedback.sent` | `피드백 보내기`를 누르면 생긴다. 보낸 의견 파일 경로가 들어 있다. 에이전트가 읽은 뒤 지운다 |
| `<덱>-feedback.done` | `검수 완료`를 누르면 생긴다. 보낸 의견 파일 경로가 들어 있다. 이후 서버는 의견을 받지 않는다 |
| `<덱>-feedback-history/` | 보낸 의견. `피드백 보내기`와 `검수 완료`가 보낼 때마다 시각별 파일로 옮긴다 |
