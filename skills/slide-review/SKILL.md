# 슬라이드 검수

사람이 덱을 보면서 고칠 곳을 가리키고, 에이전트가 그 지점을 정확히 찾아 고치게 한다. 대화로 받은 피드백은 어느 장의 어느 요소인지 불분명하고, 같은 피드백을 두 번 전달하게 만든다. 이 스킬은 의견을 요소 단위로 기록해 그 문제를 없앤다.

## 원칙

1. **의견은 요소를 가리킨다.** 의견마다 장 번호, 요소 종류, 요소 문구 일부, 장 기준 CSS 경로가 붙는다. 에이전트는 이 정보로 요소를 찾는다.
2. **의견은 잃어버리지 않는다.** 입력하는 즉시 서버에 저장된다. 버튼을 누르지 않고 다른 장으로 넘어가도 남는다.
3. **검수가 끝난 시점은 사용자가 정한다.** 에이전트는 `검수 완료` 신호가 올 때까지 기다리고, 그 전에 의견을 읽어 작업을 시작하지 않는다.

## 검수 화면

`assets/review.html`이 화면이고 `scripts/review_server.py`가 덱과 화면을 제공하고 의견을 저장한다.

| 자리 | 기능 |
|---|---|
| 상단 막대 | 덱 이름, `◀ 4/9 ▶` 장 이동, `요소 선택` 켜기·끄기, `비율`, `표시`, `PDF 가로`, 저장 상태, `HTML 저장`, `PDF 저장`, `검수 완료` |
| 왼쪽 | 덱(덱의 비율 또는 고른 비율). 요소에 마우스를 올리면 점선 테두리, 클릭하면 선택된다. 같은 요소를 다시 클릭하면 상위 블록으로 넓어진다. 의견을 단 요소에 번호 핀이 붙는다 |
| 오른쪽 | 현재 장 제목, 선택한 요소의 의견 입력, 이 장의 의견 목록(누르면 요소 강조와 수정), 장 전체 의견, 의견이 있는 장 번호 |

- `요소 선택`이 켜져 있으면 클릭으로 장이 넘어가지 않는다. 장 이동은 버튼이나 `←`/`→`이다.
- `비율`(덱 설정, 16:9, 16:10, 4:3, 3:2, 1:1, 21:9), `표시`(맞춤, 50~150%, 100%는 PDF 쪽 실제 크기), `PDF 가로`(16, 13.33, 11.69, 20인치, 직접 입력)는 검수 화면과 PDF에만 적용한다. 덱 HTML 파일은 바꾸지 않는다. 덱 설정 비율은 덱의 `<html data-ratio>`이고, 없으면 16:9이다.
- `HTML 저장`과 `PDF 저장`은 Chrome·Edge에서 브라우저 저장 창으로 위치와 파일 이름을 묻는다. Safari·Firefox에는 이 창이 없어 브라우저의 다운로드 설정을 따른다.
- PDF는 서버가 Chrome·Chromium·Edge로 렌더링한다. 지금 보는 언어, 고른 비율과 가로 길이로 장마다 한 쪽을 만든다. 덱에 단계(`data-step`, `data-steps`)가 있으면 단계마다 별개의 쪽이 된다. Chrome은 쪽 크기를 반올림하므로 서버가 쪽 크기를 정확한 값으로 고친다. 브라우저 인쇄 창은 쓰지 않는다. Safari처럼 쪽 크기 지정을 무시하는 브라우저에서 장이 잘리기 때문이다.
- 글꼴: 서버는 덱을 보여 줄 때와 PDF를 만들 때 이 스킬에 들어 있는 Pretendard(`assets/fonts/`, 굵기 400·500·600·700·800)를 덱에 넣는다. 그래서 검수 화면과 PDF가 같은 글꼴이고, 만드는 컴퓨터에 Pretendard가 없어도 PDF에 Pretendard가 들어간다. 덱 파일은 바꾸지 않는다. 덱이 `font-family`에서 Pretendard를 쓰지 않으면 덱이 지정한 글꼴을 쓴다.
- 덱의 장은 `<section class="slide">`이고, 없으면 `<section>`이다. 장 이동은 덱이 받는 `←`/`→` 키를 검수 화면이 대신 보낸다. 이 두 조건을 갖춘 덱이면 어느 도구로 만들었든 검수할 수 있다.

## 절차

1. **서버를 띄우고 화면을 연다.** 덱 폴더(또는 그 상위 폴더)를 루트로 백그라운드에서 실행한다.

   ```bash
   python3 <스킬 폴더>/scripts/review_server.py <루트 폴더> --port 8765 --open <루트 기준 덱 경로>
   ```

   `--open`이 브라우저에 `http://localhost:8765/__review/<덱 경로>`를 연다. 서버가 이미 떠 있으면 다시 띄우지 않고 그 주소를 `open`(macOS)이나 `xdg-open`(Linux)으로 연다. 포트가 사용 중이면 다른 포트를 쓴다.

2. **사용자에게 알린다.** 무엇을 보면 되는지, 요소를 클릭해 의견을 달고 `검수 완료`를 누르면 된다는 것만 짧게 쓴다.

3. **완료를 기다린다.** `검수 완료`를 누르면 덱 옆에 `<덱 이름>-feedback.done`이 생긴다. 이 파일이 생길 때까지 기다린다.

   ```bash
   until [ -f <덱 경로에서 .html을 뺀 것>-feedback.done ]; do sleep 2; done
   ```

4. **의견을 읽는다.** `<덱 이름>-feedback.md`가 사람이 읽는 형태이고 `<덱 이름>-feedback.json`이 같은 내용의 구조 데이터이다.

   ```markdown
   ## 5. 위키 검색 답변 정답률 61% → 74%
   - 슬라이드 전체: 내용이 문장으로 길어 와닿지 않는다
   - 1. 제목 "위키 검색 답변 정답률 61% → 74%" (`header:nth-child(1) > h2:nth-child(2)`): 대상이 보이지 않는다
   ```

   CSS 경로는 장(`section`) 기준이다. `section.querySelector(':scope > ' + 경로)`로 요소를 찾는다.

5. **반영한다.**
   - 덱만 고치는 요청이면 의견마다 해당 요소를 고친다.
   - 덱을 만든 스킬을 고치는 중이면, 의견을 덱 하나의 수정으로 끝내지 않는다. 의견이 가리키는 원칙을 찾아 스킬 문서의 해당 원칙을 다시 쓴다. 문장을 덧붙이지 않는다.
   - 지금까지 받은 의견을 누적 목록으로 남기고, 새 덱을 사람에게 보이기 전에 목록 전체와 대조한다. 이전 의견이 다시 어긋나면 고친 뒤에 보인다.

6. **다시 연다.** 새 덱을 같은 방법으로 연다. 이전 덱의 `-feedback.done`은 새 덱과 파일 이름이 다르면 그대로 둔다. 같은 파일을 다시 검수받으면 `-feedback.done`을 지운 뒤 연다.

## 파일

| 파일 | 내용 |
|---|---|
| `scripts/review_server.py` | 루트 폴더 정적 제공, `/__review/<덱>`에 검수 화면, `POST /__feedback`으로 의견 저장, `/__render/<덱>`에 글꼴을 넣은 덱, `/__pdf/<덱>?lang=&ratio=&w=`으로 PDF 생성 |
| `assets/review.html` | 검수 화면 |
| `assets/fonts/` | Pretendard 정적 글꼴 5개와 라이선스(SIL Open Font License 1.1) |
| `<덱>-feedback.md` | 의견, 사람이 읽는 형태 |
| `<덱>-feedback.json` | 의견, 구조 데이터. 검수 화면을 다시 열면 이 파일에서 의견을 불러온다 |
| `<덱>-feedback.done` | `검수 완료`를 누르면 생긴다. 이후 의견을 고치면 지워진다 |
